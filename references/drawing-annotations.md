# Drawing semantics: annotations, GTols, weld symbols and BOMs

Runnable original examples: [create_three_views.bas](../recipes/drawings/create_three_views.bas), [inspect_drawing_semantics.bas](../recipes/drawings/inspect_drawing_semantics.bas). Standard three-view creation and inspection of the resulting view-only fixture passed on SOLIDWORKS 2026 SP4 (34.4.0); [scope/evidence](../recipes/drawings/README.md). GTol/weld/BOM positive branches remain **NOT_LIVE_TESTED**. Installed R2026x static API checks passed. Creation leaves a new unsaved drawing for review; inspection reads annotation text and tables. Neither recipe certifies a manufacturing drawing.

## Creating standard views without localized names

`SldWorks.NewDocument(templatePath,paperSize,width,height)` returns the new model document; check Nothing and drawing type. The [official contract](https://help.solidworks.com/2021/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.ISldWorks~NewDocument.html) requires a full template path and uses width/height only for custom paper. A `.drwdot` is a document template, not a `.slddrt` sheet-format file. The recipe accepts an explicit local template or the user's default template preference; it does not invent an installation path.

[Create3rdAngleViews2(modelPath)](https://help.solidworks.com/2018/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IDrawingDoc~Create3rdAngleViews2.html) creates the standard orthographic layout and honors automatic scaling. It avoids localized named-view strings. The recipe requires a saved/clean part copy, checks the Boolean result/rebuild and counts model views after excluding sheet pseudo-views; each [GetReferencedModelName](https://help.solidworks.com/2011/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IView~GetReferencedModelName.html) must match the input path. Inspect orientation, spacing and scale visually on a fixture: three objects are not a layout-quality guarantee.

After creation, `ActivateDoc3` restores the original part without requesting a rebuild, using a filename including extension and checking returned type/path. Its [activation contract](https://help.solidworks.com/2027/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.ISldWorks~ActivateDoc3.html?id=4.1.383.1.0) allows a needs-rebuild warning even when the document is activated; the macro prints the status. The new drawing stays unsaved/open even on partial failure; neither input nor output is saved or automatically closed.

## Traversal and annotation dispatch

[DrawingDoc.GetViews](https://help.solidworks.com/2016/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IDrawingDoc~GetViews.html) returns an array of arrays. Each inner array starts with the sheet pseudo-view; the outer order is unspecified. Include that first entry for sheet-level annotations. [View.GetName2](https://help.solidworks.com/2025/english/api/sldworksapi/solidworks.interop.sldworks~solidworks.interop.sldworks.iview~getname2.html) is a label, not a universal unique key.

Read `GetAnnotationCount` before `GetAnnotations`, guard empty arrays, and use [Annotation.GetType](https://help.solidworks.com/2021/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IAnnotation~GetType.html) with [swAnnotationType_e](https://help.solidworks.com/2024/english/api/swconst/SolidWorks.Interop.swconst~SolidWorks.Interop.swconst.swAnnotationType_e.html?id=ec2cc9e689544b5bba4747eb4603a073). [GetSpecificAnnotation](https://help.solidworks.com/2019/english/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IAnnotation~GetSpecificAnnotation.html) can return Nothing for PMI-only data; those need `GetPMIType`/`GetPMIData`. Cast only after type inspection. [Note.GetText](https://help.solidworks.com/2027/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.INote~GetText.html) reads note text; do not replace linked-property expressions with evaluated text when editing.

## GTol and weld-symbol inspection

For GTols, [GetFrameCount](https://help.solidworks.com/2026/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IGtol~GetFrameCount.html) reports stored frames, including frames that may not display. [GetTextCount](https://help.solidworks.com/2025/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IGtol~GetTextCount.html) and [GetTextAtIndex](https://help.solidworks.com/2022/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IGtol~GetTextAtIndex.html) expose text using zero-based indexes. Text alone does not encode every symbol, modifier, tolerance-zone setting or attachment.

Version matters: [GetFrameValues](https://help.solidworks.com/2023/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IGtol~GetFrameValues.html) is valid only for GTols created before SOLIDWORKS 2022 and takes a one-based frame number. Do not reuse that contract for modern GTol frames. The [GTol member index](https://help.solidworks.com/2024/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IGtol_members.html) identifies modern frame APIs, symbols, datum identifiers and leader/attachment access. Select the appropriate representation before editing a GTol.

For weld symbols, [GetTextCount](https://help.solidworks.com/2017/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IWeldSymbol~GetTextCount.html) and [GetTextAtIndex](https://help.solidworks.com/2021/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IWeldSymbol~GetTextAtIndex.html) read zero-based text items. [GetText(WhichText)](https://help.solidworks.com/2016/english/api/sldworksapi/solidworks.interop.sldworks~solidworks.interop.sldworks.iweldsymbol~gettext.html) instead uses `swWeldSymbolTextTypes_e`. These parameter domains are different. A visible weld symbol is an annotation, not evidence that a 3D weld bead or weldment body exists.

## BOM and other tables

[View.GetTableAnnotations](https://help.solidworks.com/2023/english/api/sldworksapi/solidworks.interop.sldworks~solidworks.interop.sldworks.iview~gettableannotations.html?format=P&value=) returns table objects. Inspect `TableAnnotation.Type`; use total row/column counts to include hidden cells. [DisplayedText2(row,column,includeHidden)](https://help.solidworks.com/2023/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.ITableAnnotation~DisplayedText2.html) is a zero-based, read-only evaluated display string; `Text2` is the parameterized expression. The [table member index](https://help.solidworks.com/2022/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.ITableAnnotation_members.html) distinguishes hidden/total counts and these properties.

For component identity, use [BomTableAnnotation.GetComponents2(row,configuration)](https://help.solidworks.com/2021/english/api/sldworksapi/solidworks.interop.sldworks~solidworks.interop.sldworks.ibomtableannotation~getcomponents2.html), not a displayed part-number cell. Configuration is required for top-level-only row lookup; parts-only/indented lookup uses an empty string. Quantities also depend on BOM type, configuration visibility, excluded components and dissolved/promoted subassemblies.

For creation, [View.InsertBomTable4](https://help.solidworks.com/2023/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IView~InsertBomTable4.html) takes ten parameters: anchor flag, X/Y, anchor type, BOM type, configuration, template, hidden flag, indented numbering type and detailed-cut-list flag. Validate the `.sldbomtbt` template/BOM-type pairing and return object. Its top-level-only creation contract delegates configuration selection to `BomFeature` configuration APIs; do not confuse that with row lookup's configuration argument. No BOM-creation execution is claimed by this inspection recipe.
