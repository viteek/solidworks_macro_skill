# Create views and inspect drawing semantics

[create_three_views.bas](create_three_views.bas) creates a new **unsaved** drawing from an active saved/clean part copy. Configure `DRAWING_TEMPLATE` with an existing local `.drwdot`, or leave it empty to use the SOLIDWORKS default drawing template preference. Use a blank template; the recipe requests standard A-size paper. Import one module at a time into a SOLIDWORKS VBA project with SOLIDWORKS/constants references and compile before running `main`.

Expected result: a new unsaved drawing with standard third-angle orthographic views; successful rebuild; at least three model views whose referenced model paths all match the part. Layout follows the template and SOLIDWORKS automatic view scaling. The original part is reactivated without a requested rebuild and its type/path are checked. The output drawing remains open for review. Neither document is saved or closed; failure can leave a partial unsaved drawing.

Document restoration runs in a protected cleanup section reached with `Resume Cleanup` after an error. Preflight errors before a new document exists do not request reactivation. A failed restoration produces FAIL and preserves the original failure text; it does not close documents or invoke an automatic save.

Negative cases: no/wrong/unsaved/dirty input part, missing or wrong-extension template: reject before creating a document. View creation/rebuild/path mismatch or failed input reactivation: report the failure and any remaining drawing. Positive fixture verification must inspect view orientation, spacing/scale, actual part configuration, original active document and unsaved drawing path. This recipe does not infer that three returned views guarantee a readable manufacturing layout.

## Inspect existing drawings

[inspect_drawing_semantics.bas](inspect_drawing_semantics.bas) is an original standalone, read-only VBA macro. Import it into a SOLIDWORKS VBA project with SOLIDWORKS and constants references, compile, open a drawing, show the Immediate window (Ctrl+G), run `main`. Minimum API level: SOLIDWORKS 2018 (`DisplayedText2`). No file paths or localized view names are hard-coded.

Inputs: an active drawing, ideally a test fixture with two sheets, a sheet note, a model view note, a GTol, weld symbol and BOM/general table including a hidden row or column. The macro includes each sheet pseudo-view, logs annotation types and note text, GTol stored-frame counts and text items, weld text items, and every table's displayed cell contents including hidden cells. It does not activate sheets, modify selection, rebuild or save.

Expected result: a labeled report for each sheet/view, readable annotation text and zero-based cell coordinates. Sheet arrays are not assumed to match sheet tab order. GTol text is diagnostic output, not a complete interpretation of tolerance symbols/modifiers; BOM displayed text does not establish component identity or engineering quantity. Some objects may appear through more than one view/table relationship: do not sum this report as a unique-object inventory.

Negative cases: no document and non-drawing documents produce a message; an empty drawing/sheet or a view without annotations/tables completes without a null-array error. A PMI-only annotation may have no specific object and is reported explicitly. Detached, detailing-mode, hidden/suppressed and stale drawing data must be compared with a resolved fixture before relying on the report. Large tables intentionally produce large Immediate-window output.
